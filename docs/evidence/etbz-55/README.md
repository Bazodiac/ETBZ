# ETBZ-55 — fixture-first PresentationProjection and PDF

The first real `application/pdf` of the Bazodiac product: the D4 golden input (the
synthetic known-time chart, "Musterkundin A", no real birth data; PO decision of
2026-09-28, Jira ETBZ-2 comment 16690) and the versioned German text payload of the
ETBZ-52 controlled fixture run, projected by `buildPresentationProjection` onto the one
template `bazodiac-final-template@1.0.0` and rendered by the local
`bazodiac-pdf-renderer@1.0.0` (`tools/pdf-renderer/`). Decision record: ADR 0012.

## Files

| File | What it is | Produced by |
| --- | --- | --- |
| `presentation-projection.json` | the complete page model: every page, value, label and long-form line position; `customerStrings`, `displayGlyphs`, `cjkText`; hash-bound | `npm run etbz55:projection`; regenerated byte-identically by the contract suite |
| `bazodiac-reading.pdf` | the rendered document, 29 A4 pages | the renderer, run 3 of 3 |
| `contact-sheet.png` | all 29 pages, for visual inspection | the renderer |
| `qa-report.json` | every check of the render, per page, including the platform faces Chromium used | the renderer |
| `artifact-manifest.json` | PDF digest, length and page count; input, presentation, template, renderer and font identities; QA state; the declared generation record | the renderer |

`tests/contract/etbz55-presentation-evidence.contract.test.ts` re-derives in CI every
claim that does not need a browser: the projection from the fixtures, the metrics from
the Inter binaries, and every digest the manifest states (PDF, contact sheet,
projection file, template, renderer sources, fonts). The generation record is the
operator's declaration (`declared: true`), made on the repository head the render ran
on — the base of the delivering pull request.

## What the render shows

- Four Pillars, Hidden Stems and Ten Gods exactly as the validated chart states them —
  every value cross-checked against the glyph contract and against the fact set the
  Skill was handed (`tests/unit/etbz55-presentation.test.ts`).
- The Wu Xing distribution as supplied (`1.8 · 2.5 · 2 · 2 · 2`), through the one
  registered transform `pt.linear-max-v1`; no dominance, no balance.
- Seven chapters of 603–673 words, each over two pages; the page breaks are the
  projection's, computed by the TypeScript port of the canonical ETBZ-49 paginator,
  which reproduces the canonical build's recorded layout line for line.
- Only the 27 display glyphs as vector assets; every other Hanzi in the pinned Noto
  Sans CJK SC face; Inter for Latin text. No host fallback face (platform-font scan).
- Deterministic: runs 2 and 3 produced the same PDF bytes and the same 29 page images.

## What it does not show

- `ChartMotifSummary` and `ChapterDivider` — the template contract (ETBZ-43 / ETBZ-49)
  defines no such components; `KeyInsightPanel` exists only as an atomic long-form
  block and the payload carries none. Motif and claim bindings arrive with the Skill
  output in ETBZ-56.
- The Day-Master content slots (`dayMaster.reading`, `dayMaster.pillarReading`) — the
  fixture payload carries no approved content for them; they are left empty and listed
  in `emptyContentSlots`, never filled with stock copy.
- An unknown birth time — refused (`PRESENTATION_UNKNOWN_TIME_UNSUPPORTED`); the
  template defines no unknown-time rendering.
- Whether the document is *sellable* — that is the human verdict of ETBZ-54.

## Observations for the human verdict and the contract owners

- A paragraph that crosses from the two-column opener onto a continuation page keeps
  the wrap of the opener column, so its first lines on the continuation page are
  narrower than the rest. This is the canonical ETBZ-49 paginator's behaviour, which
  the port reproduces on purpose.
- German Qi-role labels (`Haupt-Qi`, `Mittleres Qi`, `Rest-Qi`) are template labels;
  the Lexicon v1 carries no German wording for Qi roles.
- The payload addresses the reader informally (du); the template labels follow.
