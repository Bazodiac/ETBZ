# ETBZ-55 — fixture-first PresentationProjection and PDF

The first real `application/pdf` of the Bazodiac product: the D4 golden input (the
synthetic known-time chart, "Musterkundin A", no real birth data; PO decision of
2026-09-28, Jira ETBZ-2 comment 16690) and the versioned German text payload of the
ETBZ-52 controlled fixture run, projected by `buildPresentationProjection` onto the one
template `bazodiac-final-template@1.0.0` and rendered by the local
`bazodiac-pdf-renderer@1.0.0` (`tools/pdf-renderer/`). Decision record: ADR 0012.

## Files

| File | What it is | Produced by |
| --- | --- | --- |
| `presentation-projection.json` | the complete page model: every page, value, label and long-form line position; each page's printed `strings`, their union `customerStrings`, `displayGlyphs`, `cjkText`; hash-bound | `npm run etbz55:projection`; regenerated byte-identically by the contract suite |
| `bazodiac-reading.pdf` | the rendered document, 29 A4 pages | the renderer, run 3 of 3 |
| `contact-sheet.png` | all 29 pages, for visual inspection | the renderer |
| `qa-report.json` | every check of the render, per page, including the platform faces Chromium used, and the ink band (lowest and highest share) each kind left on the page images | the renderer |
| `artifact-manifest.json` | PDF digest, length and page count; input, presentation, template (with its four drawing assets), renderer and font identities; QA state; the declared generation record | the renderer |
| `renderer-canaries.json` | 115 executed negative runs: every renderer check and finding code broken at least once except the six ADR 0012 limitation 8 names, each run BLOCKED at the expected check with no PDF and no manifest (the `partial-write` run instead proves that no output directory appears); bound to the renderer and canary source digests; plus the differential test of the renderer's hash mirror against the TypeScript `canonicalJson` | `tools/pdf-renderer/qa/run_canaries.py` |

`tests/contract/etbz55-presentation-evidence.contract.test.ts` re-derives in CI every
claim that does not need a browser: the projection from the fixtures, the metrics from
the Inter binaries, every digest the manifest states for a committed file (PDF, contact
sheet, projection file, template and its drawing assets, renderer sources, Inter faces),
and the canary record against the same renderer digest. Three things CI cannot
re-derive are stated as such: the Noto Sans CJK face is a pinned literal (a host font,
not committed), the QA report's per-page image digests are recorded only (the page
images are not committed), and the engine versions are a declaration.

The generation record is the operator's declaration (`declared: true`). The render ran
from an uncommitted working tree on top of the `repositoryHead` it names, the head of the
delivering pull request before this evidence was committed. The renderer is identified
by `renderer.sourceSha256` and the input by `presentation.structuralHash`; CI re-derives
both against the committed tree.

## What the render shows

- Four Pillars, Hidden Stems and Ten Gods exactly as the validated chart states them.
  Every stem, branch, animal and Wu Xing value, and every hidden stem with its phase, Qi
  role and Ten-God relation, is compared value by value with the natal chart and with the
  fact set the Skill was handed (`tests/unit/etbz55-presentation.test.ts`). The Ten Gods
  page marks four presence states: visible stem, hidden stem, both, not present.
- The chart's source warning as a data note on the identity page and on the method page,
  in template wording, never as a code.
- The Wu Xing distribution as supplied (`1.8 · 2.5 · 2 · 2 · 2`), through the one
  registered transform `pt.linear-max-v1`; no dominance, no balance.
- Seven chapters of 603–673 words, each over two pages; the page breaks are the
  projection's, computed by the TypeScript port of the canonical ETBZ-49 paginator,
  which reproduces the canonical build's recorded layout line for line.
- Only the 27 display glyphs as vector assets; every other Hanzi in the pinned Noto
  Sans CJK SC face; Inter for Latin text, checked per element. Every face that set text
  is one of six exact PostScript names (platform-font scan).
- On every page every printed string, drawn glyph, presence mark and phase colour is the
  projection value at its path, inside its own entry's slots and in list order, every
  long-form line at its computed position and every table mark under its column; all of
  it is visible and leaves its own colour on the page image, and every path the page
  must show is shown.
- Deterministic: runs 2 and 3 produced the same PDF bytes and the same 29 page images,
  and a separate two-run render process produced the same PDF bytes again.

## What it does not show

- `ChartMotifSummary` and `ChapterDivider` — the template contract (ETBZ-43 / ETBZ-49)
  defines no such components; `KeyInsightPanel` exists only as an atomic long-form
  block and the payload carries none. Motif and claim bindings arrive with the Skill
  output in ETBZ-56.
- The Day-Master content slots (`dayMaster.reading`, `dayMaster.pillarReading`) — the
  fixture payload carries no approved content for them; they are left empty and listed
  in `emptyContentSlots`, never filled with stock copy.
- An unknown birth time — refused (`PRESENTATION_UNKNOWN_TIME_UNSUPPORTED`); the
  template defines no unknown-time rendering.
- Whether the document is *sellable* — that is the human verdict of ETBZ-54.

## Observations for the human verdict and the contract owners

- A paragraph that crosses from the two-column opener onto a continuation page keeps
  the wrap of the opener column, so its first lines on the continuation page are
  narrower than the rest. This is the canonical ETBZ-49 paginator's behaviour, which
  the port reproduces on purpose.
- German Qi-role labels (`Haupt-Qi`, `Mittleres Qi`, `Rest-Qi`) are terminology labels
  for FuFirE's three hidden-stem roles; the Lexicon v1 carries no German wording for Qi
  roles.
- The first round-2 render showed the sidebar's Day-Master line running out of its
  panel on the four continuation pages with a sidebar. The QA then gained the container
  check that caught it, and the `overflows-container` canary reproduces that defect.
- The payload addresses the reader informally (du); the template labels follow.
- Cosmetic, for the human verdict: a line may end on a `·` separator (the wrap
  opportunity sits after it); on the identity page the data note "Siehe
  Methodenhinweis, Seite 29" can wrap before its page number (it is one projection
  string). The running head now paints above the atmosphere blobs, so the four-pillars
  head tag is no longer tinted by the fire blob, as it was in the approved ETBZ-49 page 05.
