# ETBZ-52 — controlled fixture run of Bazodiac Interpretation Skill v1

The first controlled execution of `bazodiac-interpretation-skill@1.0.0`: the synthetic known-time fixture chart (Geng/Wu · Ren/Wu · Xin/Hai · Yi/Wei, subject "Musterkundin A", no real birth data) through the whole chain, the reading written in the Claude runtime available to the Delivery Runner (PO decision D2 of 2026-09-28, Jira ETBZ-2 comment 16690), and accepted by `acceptSkillReading` on the first accepted attempt after two refusals that were repaired in the reading only.

## Files (`fixture/`)

| File | What it is | Produced by |
| --- | --- | --- |
| `skill-input.json` | the `bazodiac-skill-input.v1` package the runtime was handed: interpretable facts, accepted claim graph, accepted plan, source warnings, contract set, allowed slot ids | `tests/support/skillFixture.ts` → `buildSkillInputPackage`; regenerated byte-identically by the contract suite |
| `skill-reading.json` | the reading the runtime returned, as returned (JSON only) | the Claude runtime, from `skill/bazodiac-interpretation-skill-v1/SKILL.md` |
| `accepted-reading.json` | the same reading as accepted by the boundary, with its `structuralHash` | `acceptSkillReading` |
| `customer-reading.json` | the text-only customer projection: no id, hash, code or state | `projectCustomerReading` |
| `manifest.json` | measured hashes of everything above plus the declared generation record (runtime, model, date, operator, the repository head the run was executed on — the base of the delivering PR, not its head) | `scripts/etbz52-fixture-manifest.mjs` |

`tests/contract/etbz52-skill-fixture-run.contract.test.ts` re-derives every measured value on every run: the package from the fixtures, the acceptance of the reading, the projection, every file digest and every hash in the manifest. The generation record is a declaration by the operator and is marked as such (`declared: true`); nothing in the repository can prove which model wrote a text.

## What the run shows and does not show

- The reading renders exactly the plan's seven chapters (ESTABLISH, REINFORCE, CONTRAST, CONTEXTUALIZE, QUALIFY, CONTRAST, INTEGRATE), every planned claim in its chapter, declared semantic deltas and callbacks, three grounded reflection questions, the source warning verbatim in the method note, and visualization specs over facts and planned claims only. Each chapter is inside the 600–900-word long-form budget.
- The reading is German. The ETBZ-25 citation rule treats every stem and branch name as a chart symbol, including the branch `You`; English second-person prose therefore cannot pass the rule, while German prose can. The Lexicon carries DE wording for every term the reading uses.
- No fact carries the value `metal`: the Day Master's element is recorded as `Metall` by the source. Element names therefore appear only in FACT paragraphs quoting the source label. The Lexicon has no customer wording per element; this is recorded as an observation for the Lexicon's owner, not repaired here.
- Two refusals preceded acceptance, both repaired in the reading and neither in the boundary: `READING_UNCITED_SYMBOL` — the word "Verantwortung" is the German label of a Ten God and was not a cited value in that paragraph; `READING_CHAPTER_LENGTH_OUT_OF_CONTRACT` — three chapters were shorter than the 600-word floor.
- Not shown: whether any sentence is *true* of a person (no reading can show that), and the Anti-Boilerplate checks 6.1–6.7, which need a second reading and are ETBZ-54's.
- Review revision (2026-09-28, PR #16 round 1): `SKILL.md` was revised — a `FACT`/`FRAME` paragraph over a provisional fact is written `TENTATIVE`, a FACT paragraph carries no claim, framing is not rendering, every first rendering is declared `NEW_CLAIM`, no external tool — and the boundary tightened accordingly (the symbol rule now also covers the reading title, chapter titles and the method note; new code `READING_NEW_CLAIM_UNDECLARED`). The reading was not changed: it is re-accepted unchanged under the revised boundary (same `acceptedReadingStructuralHash`), and `manifest.json` was regenerated for the revised package hash.
